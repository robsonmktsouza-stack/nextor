# Lumeron ERP v1.0.0 — primeira base estável

**Aprovação para versionamento do código:** 20/10/2026.
**Produto:** Nextor / Lumeron ERP; repositório `robsonmktsouza-stack/nextor`.
**Natureza da entrega:** tag de versão Git correspondente à linha estável `main`, **não é implantação automática nem atestado de emissão efetiva em produção**.

## Escopo incluído na primeira linha estável

- PDV e vendas, controle comercial, estoque, caixa e financeiro existentes na branch funcional aprovada.
- NFC-e modelo 65 com a integração ACBrLibNFe/FFI e as regras de emissão e validação de BA implementadas até esta revisão.
- Cadastro/consulta fiscal, preparação e tratamento de status; emissão, rejeições/correções e impressão com vínculos às vendas.
- Comprovante interno de venda térmico em PDF, separado do DANFE NFC-e.
- Preparação de instâncias isoladas por CNPJ e ferramentas de provisionamento/atualização em `deploy/instances/`.
- `composer.lock` versionado e validado, para instalações reprodutíveis.
- Política de branches `main` (estável), `develop` (integração), `feature/*` (recursos), `hotfix/*` (urgência).
- CI principal com validação para `main`, `develop`, PRs e tags de release.

## Validação e rastreabilidade

A linha base foi promovida por fast-forward, sem sobrescrever histórico, após execução bem-sucedida da suíte de regressão do projeto. A criação da tag `v1.0.0` é efetuada por um workflow somente quando a última revisão da `main`, correspondente a este documento, **passar novamente no GitHub Actions**. O workflow verifica que a `main` não se moveu e se a tag já existe. Não move tags existentes.

Consultar as ações na branch `main` e a referência `refs/tags/v1.0.0` para o SHA exato de lançamento.

## Contrato para produção

A publicação é sempre explícita e **individual por CNPJ**. Nenhum push em `main`, `develop` ou `feature/*` executa automaticamente scripts de deploy. Produção exige hospedagem configurada (não `php artisan serve`), ACBr compatível com o sistema operacional, worker fiscal próprio, backups e registro das versões instaladas por cliente. A autorização real de uma NFC-e é confirmada pela SEFAZ mediante cStat/protocolo/XML correspondente, não apenas pela tag.

Os arquivos `.env`, certificados A1, CSC, senhas, XMLs privados e bancos de clientes **não fazem parte** da tag.
